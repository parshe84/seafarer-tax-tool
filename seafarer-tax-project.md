# Проект: Финансовый оптимизатор для моряков (рабочее название)

## Идея в одном предложении
Веб-сервис, который помогает моряку экономить реальные деньги — сначала на налогах, затем на денежных переводах семье, — вместо того чтобы продавать ему абстрактное «доверие» или «репутацию», как это делают существующие игроки рынка.

---

## Контекст и почему именно так

Морская индустрия уже имеет игроков, строящих репутационные/vetting-платформы (пример — Skipi: отзывы о судах, рейтинги компаний, слой доверия для банков/брокеров/P&I). Проблема таких моделей:
- классическая ловушка холодного старта двустороннего рынка (нужна критическая масса отзывов, прежде чем платформа станет полезной);
- юридический риск (репутационные обвинения в адрес компаний, риск деанонимизации);
- ценность абстрактна («доверие»), а не выражена напрямую в деньгах.

**Наш вывод:** моряки — люди, для которых зарплата и доход часто являются единственным источником обеспечения расширенной семьи. Они охотно платят за то, что даёт **прямую, измеримую, ощутимую выгоду в долларах**, и неохотно платят за абстрактную «репутацию» или «качество жизни».

Отсюда — стратегия: строить продукт вокруг денег, а не вокруг доверия.

---

## Дорожная карта (пошагово, не всё сразу)

### Шаг 1 — MVP: Налоговый оптимизатор для моряков
**Проблема:** у моряков всего мира есть налоговые льготы и вычеты (например, OFW tax exemption на Филиппинах, seafarer's earnings deduction в Великобритании, специальные режимы для украинцев, поляков, хорватов, индийцев и т.д.), о которых большинство не знает или не пользуется вовремя — и теряет тысячи долларов в год.

**Решение:** пользователь вводит:
- гражданство / страну налогового резидентства
- количество дней, проведённых в море за отчётный год
- (опционально) флаг судна, тип контракта

Сервис на выходе выдаёт:
- персонализированный пошаговый чеклист — что подать, куда, к какому сроку
- ориентировочную оценку экономии в долларах

**Почему это хороший первый шаг:**
- не требует критической массы пользователей — работает с первого же клиента;
- юридически безопасно — сервис не обвиняет компании, не собирает репутационные данные о третьих лицах;
- дешёвая и быстрая проверка гипотезы «готовы ли моряки вообще платить за цифровой продукт».

**Стартовые страны для базы правил:** Филиппины, Украина, Индия, Индонезия, Хорватия/Польша — крупнейшие поставщики морских кадров в мире.

### Шаг 2 — Оптимизатор денежных переводов (allotment)
Та же аудитория, что и в шаге 1 (люди, которым нужно переводить деньги семье регулярно и часто теряют на курсе/комиссии). Сервис сравнивает и рекомендует лучший маршрут перевода под конкретную страну назначения.
- Повышает частоту использования сервиса (retention) и LTV на одного клиента, используя уже собранную базу пользователей из шага 1.
- Технически сложнее шага 1 — зависит от партнёрств/API платёжных провайдеров.

### Шаг 3 — Монетизация существующего job-агента
У пользователя уже есть рабочий агент (Claude Code + GitHub Actions), который скрейпит вакансии с нескольких крюинг-сайтов (Martide, Crewell.net, Maritime-Zone, UkrCrewing, Berge Bulk, Oldendorff Carriers, Columbia Shipmanagement, TURTLE) и фильтрует их по рангу/типу судна/минимальной зарплате, присылая ежедневный дайджест.
- Превратить в подписочный сервис для той же базы пользователей, собранной на шагах 1–2.
- Техническая часть уже готова — нужно масштабирование под множество профилей вместо одного.

### Шаг 4 — Аукцион вакансий / групповой найм (долгосрочно)
- **Аукцион вакансий:** моряк публикует профиль и минимальную ставку один раз, несколько крюингов конкурируют за него, предлагая ставку выше базовой — переворачивает переговорную позицию в пользу моряка.
- **Групповой найм:** капитан + доверенный старпом + доверенный стармех ищут контракт вместе, одним пакетом — формализует то, что сейчас делается вручную через знакомства и WhatsApp-группы.
- Делать в последнюю очередь: это классический двусторонний рынок (нужны и моряки, и крюинги одновременно), самый рискованный и медленный элемент дорожной карты — имеет смысл запускать, когда уже есть живая база пользователей с шагов 1–3.

## Технический план для MVP (Шаг 1)

**Формат:** веб-сайт, не нативное приложение. Причины:
- скорость запуска (дни, а не недели + ревью в сторах);
- моряки часто пользуются медленным/дорогим спутниковым интернетом на борту — лёгкий сайт грузится надёжнее тяжёлого приложения;
- одна кодовая база сразу для Android, iOS и десктопа (порт/интернет-кафе);
- платежи напрямую (Stripe/PayPal, комиссия ~2-3%) без комиссии App Store/Google Play (15-30%);
- SEO — люди гуглят запросы вроде «OFW tax refund calculator», сайт индексируется поисковиками.

**Хостинг на старте — бесплатно ($0-15/год):**
- Vercel или Netlify — бесплатный тариф покрывает сайт + серверную логику (serverless functions), деплой прямо из GitHub-репозитория (знакомый пользователю процесс по аналогии с GitHub Actions);
- альтернатива — Cloudflare Pages;
- если логика простая — можно обойтись статикой + JS-калькулятором в браузере через GitHub Pages;
- база данных (когда понадобится для шага 2 и подписок) — free tier у Supabase / Neon / MongoDB Atlas хватит на первые сотни пользователей;
- единственная реальная статья расхода на старте — регистрация собственного домена (~$10-15/год), важно для доверия, так как пользователь будет вводить личные данные (гражданство и т.п.).

**Апгрейд позже:** PWA (progressive web app) — «устанавливается» на телефон как иконка без App Store, с офлайн-кэшем для плохого интернета. Нативное приложение имеет смысл рассматривать только когда появится база в тысячи активных пользователей.

---

## Ключевые принципы, которых стоит держаться

1. Не делать всё сразу — каждый следующий модуль должен финансироваться и де-рискироваться предыдущим.
2. Ценность продукта всегда должна быть выражена в конкретных долларах, а не в абстрактных понятиях доверия/репутации/качества жизни.
3. Избегать двусторонних рынков (аукцион, групповой найм) до тех пор, пока не появится собственная база пользователей с одной стороны.
4. Начинать с самого дешёвого и быстрого способа проверить готовность аудитории платить.
