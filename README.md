# Seafarer Tax Optimizer (MVP)

Веб-калькулятор налоговых льгот для моряков. Пользователь вводит гражданство,
страну налогового резидентства, количество дней в море и (опционально) флаг
судна — сервис выдаёт чеклист действий и ориентировочную оценку экономии.

## Статус

MVP-заглушка: логика расчёта в [app/api/calculate/route.ts](app/api/calculate/route.ts)
пока возвращает фиксированные тестовые данные. Реальная база налоговых правил
по странам (Philippines, Ukraine, India, Indonesia, Croatia, Poland, ...)
будет подключена позже — см. TODO-комментарии в этом файле.

## Стек

- Next.js 14 (App Router) + TypeScript
- Serverless API route (без базы данных, без хранения пользовательских данных)
- Развёртывание на Vercel

## Структура

- `app/page.tsx` — главная страница с формой
- `app/api/calculate/route.ts` — serverless-функция расчёта (заглушка)
- `app/results/page.tsx` — страница результата (чеклист + экономия)
- `app/lib/types.ts` — общие типы и список стран
- `app/lib/i18n.ts` — загрузка переводов, единственный активный язык сейчас `en`
- `messages/en.json` — весь UI-текст (английский, единственный язык на этом этапе)

## Мультиязычность (i18n)

Библиотека `next-intl` пока не подключена: при одном активном языке и без
переключателя в UI она добавила бы middleware, роутинг по локалям и конфиг,
которые сейчас не нужны. Вместо неё — простой самописный слой:

- весь видимый текст живёт в `messages/<locale>.json` (сейчас только `en.json`);
- `app/lib/i18n.ts` подгружает нужный файл и отдаёт его компонентам через
  `getMessages()` — компоненты не хардкодят текст.

Чтобы добавить новый язык (например, Filipino):
1. Создать `messages/tl.json` с тем же набором ключей, что и в `messages/en.json`.
2. Импортировать его в `app/lib/i18n.ts`, добавить `"tl"` в `locales` и в `messagesByLocale`.
3. Компоненты менять не нужно.

Переключатель языка в UI и реальный роутинг по локалям (например, `/tl/...`)
пока не добавлены — по плану это будет сделано вместе с подключением реальной
налоговой логики для соответствующей страны. Если тогда понадобится более
сложная маршрутизация или плюрализация, есть смысл мигрировать на `next-intl` —
структура `messages/*.json` для этого не потребует переписывания.

## Деплой на Vercel

1. Запушить репозиторий в GitHub.
2. В Vercel → "Import Project" → выбрать репозиторий.
3. Framework определится автоматически (Next.js), доп. настройка не требуется.
